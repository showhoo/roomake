## フレームワーク

Next.js 16（App Router）、React 19、TypeScript、Tailwind CSS。デザインツール内の状態は1つの Zustand store に収め、アニメーションは Framer Motion を控えめに使い、UI プリミティブは Radix に頼ります。フォーマットは Biome と ESLint。どちらもパスしない限り、何も出荷しません。

スタック全体の中で、残りの部分より重要な設定が2つあります。

- **サーバーコンポーネント優先。** マーケティングページ、料金ページ、法務ページ——すべてサーバーレンダリングで、クライアント JavaScript はほぼゼロ。クライアントバンドルは、インタラクティブ性が見合う場所——デザインツール——に集中させています。
- **`output: 'standalone'`。** すべての本番成果物は、自己完結するサーバーバンドルになります。Docker イメージが小さく済み、2つのリージョンデプロイメントが同一に保たれるのはこのためです（[05 · デプロイメント](05-deployment.md) を参照）。

## レンダリングパイプライン

コアのループを簡略化したものがこちらです。

1. **アップロード。** 写真1枚、最大10 MB、JPEG/PNG/WebP のみ。検証はクライアントでは UX のために、サーバーでは真実のために、二度行います。
2. **タスク作成。** クライアントは、部屋タイプと、最大4つのスタイル ID、および/または自由記述のブリーフ（最大500文字）、それに写真を送信します。タスク ID を受け取り、ポーリングします。
3. **プロンプトの組み立てはサーバー側で行う。** 強調しておきたい点です。クライアントが送るのは*スタイル ID のみ*です。スタイルプリセットを画像モデルのプロンプトへ変えるテキストの断片はサーバーにだけ存在し、クライアントバンドルには決して入りません。それこそがプロダクトのレシピ帳です。
4. **生成。** タスクエンジンがジョブを、ホスト型プロバイダー API 経由で提供される Flux 系の画像モデルへ振り分けます。手前には薄い内部ゲートウェイが1枚挟まっています。ゲートウェイが存在するのは、プロダクトコードに触れずにエンジンを機能ごとに差し替え・割り当てできるようにするためです。プロバイダーのロックインは価格リスクなので、初日から抽象化してあります。
5. **結果の受け渡し。** ビフォーアフターのペアが結果ビューにレンダリングされます。1レンダリングにつきクレジットを1消費し、失敗したレンダリングは自動で返金されます。サポートへの連絡は不要です。

画像は保存の前に sharp で後処理します（リサイズ、エンコード、メタデータの除去）。アップロードと結果はデフォルトで非公開です。`robots.txt` でクローラーから除外される*うえに*、プロキシ層で `X-Robots-Tag: noindex` を付けて配信するため、ユーザーの写真が画像検索に流れることはありません。

## アカウント、クレジット、決済

- **サインイン。** Google（One Tap）と Microsoft OAuth、さらにメールリンク。セッションは署名済みの JWT（JOSE）です。漏えいされうる独自パスワードは存在しません。
- **クレジット。** クレジットはレンダリングの単位です。残高・パック・返金は、データベースのそばにある小さな会計レイヤーに置いてあり、失敗したレンダリングの返金はタスクエンジン層で自動的に行われます。
- **決済。** 国際チェックアウトは **merchant of record（マーチャント・オブ・レコード）としての Creem** を通します。決済側の税務とコンプライアンスの負担を担ってもらえるのは、世界に販売する小さなチームにとって妥当な取引です。中国サイトは、別個のローカライズされたチェックアウトを運用します。Webhook ハンドラは冪等で、検証済みです。課金の経路でクライアントを信頼する箇所は何一つありません。

## データ層

SQLite を、型付きの薄いデータアクセスレイヤー経由で使います。書き込み量が控えめな、隔離された2つのデプロイメントという条件では、組み込みデータベースは運用対象を丸ごと一つ消してくれます（パッチを当てるべきデータベースサーバーが存在せず、バックアップ＝ファイルのコピー）。書き込み量がそうでないと言い出す日が来たら、変更が必要なのはデータアクセスレイヤーだけです。トランザクションメールはプレーンな SMTP で送ります。

## アナリティクスとプライバシー

アナリティクスは**セルフホストかつクッキーレス**です。サードパーティの広告トラッカーはなく、EU 訪問者への同意バナーもなく、データの転売もありません——アナリティクスの判断は GDPR への姿勢と一緒に決めたものであり、後から付けたものではありません。ファネル分析の細やかさを手放して、一文で言い切れるプライバシーの説明を手にしました。このプロダクトにとって、その取引は正しいものです。

## 盗む価値のある自動チェック

- **ゴールデンマスター HTML diff。** ページコードに触れるリファクタリングの前には、コアページのレンダリング済み HTML を記録し、リファクタリング後には diff が空であることを要求します。6ロケールの辞書抽出を視覚リグレッションゼロでやり切ったのは、この方法だからです。
- **バンドル予算。** デザインツールのクライアント chunk には明示的なサイズ上限があります。上限を吹き飛ばす辞書や機能は、分割されるか、却下されます。
- **スクリプト化された SEO アサーション。** サイトマップのエントリ、hreflang の相互参照、canonical/OG URL（「canonical URL は実際に 200 を返すこと」を含む）は、目で見て確認するのでなくスクリプトで検査します。[04 · SEO プレイブック](04-seo.md) を参照してください。
