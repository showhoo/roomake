# 04 · SEO プレイブック — 技術 SEO、構造化データ、そして誠実な AI クローラーポリシー

## メタデータ生成器は1つ、手書きの meta はゼロ

すべてのページのタイトル、説明、canonical、Open Graph/Twitter カード、robots meta、hreflang のセットは、単一の型付き生成器から出力されます。ページごとの手書きは一切ありません。だからこそ、meta のドリフト——canonical の重複、hreflang の欠落、タイトルの腐敗——が静かに起こりようがないのです。メタデータを設ける価値があるなら、生成する価値もあります。

## SEO のための URL とロケールの方針

- **サブディレクトリ方式のロケール**（`/ja`、`/de`…）: シグナルは1つのドメインに集中します。サブドメインは権威を分け、パラメータはクロールを分けます。
- **`Accept-Language` による自動リダイレクトはしない。** 断じて。Googlebot に誤った言語変体を与えるうえ、CDN キャッシュを UA ごとに分断します。hreflang と目に見える言語スイッチャーの組み合わせが正解であり、自動リダイレクトは魅力的に見える誤った答えです。
- 公開ページには **Cookie ベースのロケール記憶を使わない**: 最初のアクセスは、クローラーが再現できなければなりません。
- **`x-default` は英語を指す**（デフォルト言語での体験）。

## hreflang: 相互参照するか、まったくやらないか

運用しているルールはこうです。**hreflang は、真に 1:1 の等価であるページだけを結び付け、集合の全メンバーが必ず相互に参照し返す。** コアページ（ホーム、ツール、料金）は、完全で、生成され、スクリプトで検証済みのクラスタを形成しています。

ローカライズされた編集コンテンツはクラスタに*参加しません*: 言語別のガイドは、各市場向けにネイティブに書かれています——題材も異なる、切り口も異なる——つまり等価なページではないため、等価と印を付けることは、回りくどい形で検索エンジンに嘘をつくことになります。非等価なローカライズページには、クリーンな self-canonical だけを与え、`alternates` は付けません。不完全な hreflang と不誠実な hreflang のどちらかを選ぶしかないなら、どちらも選びません。

サイトマップのエントリも同じ方針に従います。`xhtml:link` の alternates は等価な URL にだけ付け、「ルート × ロケール」の行列として生成し、法務ページは EN のみのエントリにします。

## canonical の衛生管理（実際にリリースしてしまったバグ）

一時期、ロケールのホームページが `/ja/` のような——末尾にスラッシュの付いた——canonical を出力していました。一方、サイトの正規 URL の形式はスラッシュなしです。すべての canonical と `og:url` が 308 リダイレクトを指した状態でした。Google Search Console はこれを「ページがリダイレクトされています」と報告し、重複シグナルは希釈されていきますが、ブラウザでは何も壊れて見えません。2つの修正を加え、今ではどちらも恒久のルールにしています。

1. canonical URL を組み立てる地点で末尾スラッシュを正規化する（ルート `/` は除く）。
2. すべての canonical/OG URL を解決して HTTP 200 を要求するアサーションスクリプト。3xx リダイレクトになる canonical はビルド失敗として扱います。

## 構造化データは、意図して選ぶ

- **含めるもの**: `Organization`（legal name を含む）、`WebSite`、`SoftwareApplication`。`availableLanguage` はハードコードではなく、有効なロケールリストから生成します。ロケールが変われば、schema も一緒に変わります。
- **意図的に外したもの**: `FAQPage` のリッチリザルト。Google は FAQ のリッチリザルトを、よく知られた権威あるサイトに限定しています。新しいドメインがこのマークアップから得られるものは何もありません。schema はチェックリストではなく、期待できる収益で決めます。

## 画像 SEO

インテリアデザインは、視覚的な検索クエリのカテゴリです。公開しているレンダリング画像には、ロケールごとにローカライズした `alt` テキスト、説明的なファイル名、高速な配信を備えています。これは検索そのものに次いで、プロダクトが持つ最も安価で、複利の効くトラフィックチャネルです。

## AI クローラー: クロール予算ではなく、答えを与える

`robots.txt` は3層のポリシーで運用しています。

| エージェントの種類 | 許可するもの |
|---|---|
| 検索エンジン | 公開ページ。アップロード/結果とアカウント領域は不許可 |
| AI アシスタント（GPTBot、Claude、PerplexityBot、…） | `/llms.txt` と `/llms-full.txt` **のみ** |
| その他全員 | 標準の公開許可リスト、crawl-delay 1 |

AI の行は見落としではなく、立場の表明です。LLM 向けのボットに必要なのは、マーケティングサイトをクロールすることではなく、*正確で最新の事実*です。そこで私たちは `llms.txt`（厳選されたインデックス: Roomake とは何か、ツールの使い方、6部屋タイプ × 34スタイル、料金モデル、ロケール、公式リンク）と `llms-full.txt`（展開版）を公開し、AI クローラーをまさにその2つのファイルへ向けます。アシスタントが「Roomake とは何か」に答えるとき、6つのキャッシュされたページから再構成させるよりも、私たち自身の要約を引用してほしい。これらのファイルは schema と同じロケールメタデータから生成されるため、現実からずれることもありません。

## キーワード: 翻訳ではなく、ネイティブ

英語のキーワードを直訳しても、検索ボリュームはゼロです。各市場には、その土地で人々が実際にどう検索するかに合わせて書かれた**ネイティブなシードリスト**を用意します。たとえば次のとおりです。

- **ja**: AI インテリア, インテリア AI, リフォーム プレビュー, 室内シミュレーション
- **de**: KI Inneneinrichtung, Wohnraum KI gestalten, Renovierung visualisieren
- **ko**: AI 인테리어, 집 꾸미기 AI, 리모델링 시뮬레이션

シードリストは、タイトル/説明に自然な形で、市場別ガイドの題材として、ロケールのメタデータに滑り込みます。キーワードの詰め込みとしては決してありません。詰め込みは検索エンジンに軽視され、読者に見放されるものです。

## 計測と検証

- Google Search Console + Bing Webmaster Tools をサイトごとに設定し、リリースのたびにサイトマップを送信します。
- **レンダリング結果から検証する。** `curl` でのヘッドリクエストは、ブラウザやクローラーが実際に見るもの（注入されたタグ、ハイドレーションによる変化、キャッシュ層）と食い違うことがあります。アサーションはレンダリング後の DOM/HTML に対して実行し、ソースだけを見て済ませません。
- ランキングはさておき、注視している先行指標: ロケールごとのインデックス済みページ数、GSC の hreflang エラー、画像検索の表示回数、AI ボットによる llms ファイルのフェッチ。

## 譲れないところでは、プライバシーが SEO に勝る

ユーザーのアップロードと生成結果が検索結果に現れることは決してありません。`robots.txt` で不許可にし、プロキシで `X-Robots-Tag: noindex` を重ねた二重の備えです。ユーザーの寝室の写真は、コンテンツマーケティングの素材ではありません。インデックスに属さないページというものは、そもそも存在するのです。

## ソフトローンチ: サイト全体を隠すのはフラグ1つ

非公開テストの間は、ビルド時の `NOINDEX` フラグ1つで、`robots.txt` がすべてに対して `Disallow: /` になります。このフラグは**デフォルトで安全側**です（環境設定の行が欠けたリリースでは、サイトは公開されるのではなく隠れます）。公開インデックスへの切替は、リリース直後に本番の `robots.txt` を読んで検証します。あらゆるキルスイッチと同じ規律です: fail closed、切替後に検証。
