## 프레임워크

Next.js 16(App Router), React 19, TypeScript, Tailwind CSS. 디자인 도구의 상태는 하나의 Zustand 스토어로 모으고, 애니메이션은 Framer Motion을 절제해서 사용하며, UI 프리미티브는 Radix에서 가져옵니다. 포매팅은 Biome에 ESLint를 더해 수행하고, 둘 다 통과해야 무엇이든 내보낼 수 있습니다.

스택의 나머지 무엇보다 중요한 설정 두 가지:

- **서버 컴포넌트 우선.** 마케팅 페이지, 가격 페이지, 법적 고지 페이지 — 전부 서버 렌더링이며 클라이언트 JavaScript는 거의 0에 가깝습니다. 클라이언트 번들은 인터랙티브성이 값을 만드는 곳, 즉 디자인 도구에만 집중되어 있습니다.
- **`output: 'standalone'`.** 모든 프로덕션 아티팩트는 자기 완결적인 서버 번들이고, 덕분에 Docker 이미지는 작아지며 두 개의 지역 배포는 동일한 형태를 유지합니다([05 · 배포](05-deployment.md) 참고).

## 렌더링 파이프라인

단순화한 핵심 루프는 다음과 같습니다:

1. **업로드.** 사진 한 장, 최대 10 MB, JPEG/PNG/WebP만 허용 — UX를 위해 클라이언트에서, 진실을 위해 서버에서 다시 한 번 검증합니다.
2. **작업 생성.** 클라이언트가 방 유형, 최대 4개의 스타일 ID 및/또는 자유 텍스트 브리프(최대 500자), 사진을 전송하면 작업 ID를 받아 폴링합니다.
3. **프롬프트 조립은 서버 측에서 일어납니다.** 강조할 가치가 있는 부분입니다. 클라이언트는 *스타일 ID만* 전송합니다. 스타일 프리셋을 이미지 모델 프롬프트로 바꾸는 텍스트 조각들은 오직 서버에만 존재하며 클라이언트 번들에는 절대 들어가지 않습니다. 그것이 제품의 레시피북입니다.
4. **생성.** 작업 엔진이 작업을, 호스티드 프로바이더 API로 서빙되는 Flux 계열 이미지 모델로 라우팅합니다. 그 사이에는 얇은 내부 게이트웨이가 있습니다. 게이트웨이가 존재하는 이유는 제품 코드를 건드리지 않고도 엔진을 교체하거나 기능별로 배정할 수 있게 하기 위함입니다 — 프로바이더 락인은 가격 리스크이므로 첫날부터 추상화해 두었습니다.
5. **전달.** 비포/애프터 쌍이 결과 뷰에 렌더링됩니다. 렌더링 1회당 크레딧 1개가 소모되고, 실패한 렌더링은 자동으로 스스로를 환불합니다 — 고객 지원 티켓이 필요 없습니다.

이미지는 저장 전에 sharp로 후처리됩니다(리사이즈, 인코딩, 메타데이터 제거). 업로드와 결과는 기본적으로 비공개입니다. `robots.txt`에서 크롤러 차단에 더해, 프록시 계층에서 `X-Robots-Tag: noindex`로 서빙되므로 사용자 사진이 이미지 검색에 끌려 들어가는 일은 없습니다.

## 계정, 크레딧, 결제

- **로그인.** Google(One Tap)과 Microsoft OAuth, 그리고 이메일 링크 방식을 지원합니다. 세션은 서명된 JWT(JOSE)입니다. 유출될 우리 쪽 비밀번호가 아예 없습니다.
- **크레딧.** 크레딧은 렌더링의 단위입니다. 잔액, 크레딧 패키지, 환불은 데이터베이스 곁의 작은 회계 계층에서 관리하며, 실패한 렌더링은 작업 엔진 수준에서 자동 환불됩니다.
- **결제.** 국제 결제는 **merchant of record인 Creem**을 통해 진행됩니다 — 결제 측면의 세금과 컴플라이언스 부담을 대신 짊어져 주기 때문에, 글로벌로 판매하는 소규모 팀에게는 합리적인 거래입니다. 중국 사이트는 별도의 현지화된 결제를 사용합니다. 웹훅 핸들러는 멱등하며 서명을 검증합니다. 결제 경로의 그 어떤 것도 클라이언트를 신뢰하지 않습니다.

## 데이터 레이어

SQLite를 타입이 붙은 얇은 데이터 액세스 레이어로 접근합니다. 쓰기 볼륨이 적당한 두 개의 격리된 배포 환경에서는 임베디드 데이터베이스가 운영 영역 하나를 통째로 없애 줍니다(패치할 데이터베이스 서버가 없고, 백업 = 파일 복사). 언젠가 쓰기 볼륨이 다른 답을 내놓더라도 바꿔야 하는 것은 데이터 액세스 레이어가 유일합니다. 트랜잭션 이메일은 일반 SMTP로 발송합니다.

## 분석과 프라이버시

분석은 **셀프 호스팅 + 쿠키리스**입니다. 서드파티 광고 트래커도 없고, EU 방문자를 위한 동의 배너도 없고, 데이터 재판매도 없습니다 — 분석에 관한 결정은 GDPR 자세와 함께, 그 이후가 아니라 동시에 이뤄졌습니다. 한 문장으로 말할 수 있는 프라이버시 스토리를 얻기 위해 퍼널 분석의 편리함을 포기했고, 이 제품에는 그 거래가 옳습니다.

## 가져가 쓸 만한 자동화 점검

- **골든 마스터 HTML diff.** 페이지 코드를 건드리는 어떤 리팩터링보다 먼저 핵심 페이지의 렌더링된 HTML을 기록하고, 리팩터링 이후에는 diff가 비어 있어야 합니다. 여섯 로캘 사전 추출을 시각적 회귀 제로로 해낸 방법이 바로 이것입니다.
- **번들 예산.** 디자인 도구의 클라이언트 청크에는 명시적인 크기 상한이 있고, 그 상한을 초과할 사전과 기능은 분할되거나 거부됩니다.
- **스크립트로 수행하는 SEO 검증.** 사이트맵 항목, hreflang 상호 참조, canonical/OG URL("canonical URL은 실제로 200을 반환해야 한다" 포함)을 눈으로 확인하지 않고 스크립트로 검사합니다. [04 · SEO 플레이북](04-seo.md) 참고.
