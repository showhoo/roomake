# 05 · 部署 —— Docker、scope 开关、缓存、回滚

[English](../en/05-deployment.md) · `简体中文` · [日本語](../ja/05-deployment.md) · [한국어](../ko/05-deployment.md) · [Deutsch](../de/05-deployment.md) · [Italiano](../it/05-deployment.md) · [Español](../es/05-deployment.md)

## 两个部署，一套镜像配方

生产环境是同一代码库的两个独立部署：

- **roomake.top** —— global 语言范围、国际收单、独立数据库与媒体存储。
- **www.roomake.cn** —— zh 单语范围、大陆本地支付、数据完全隔离。

两者运行时零共享。一边的发版事故碰不到另一边，数据故障无法越境。代价是多跑一条管线——这个代价值：区域隔离既是合规叙事，也是爆炸半径叙事。

## 构建期开关是一份契约

部署之间的一切差异都是构建期开关（语言范围、索引开关、公开 URL），在 `next build` 时内联进产物。三条规则保证它安全：

1. **改开关 = 重建，不是重启。** 运行时改环境变量对已内联的常量毫无作用——这是「以为发了版其实什么都没发」的经典姿势。
2. **危险开关默认安全。** `NOINDEX` 开关默认为*开*：环境文件少了一行的发版，产出的是隐藏的站点，绝不会是意外公开的站点。
3. **环境变量过两道白名单**——Dockerfile 的 `ARG` 声明一道，compose 的 build args 一道。过不了两道门的变量根本不进构建；配置没有第三条路可以溜进去。

发版仪式，按序：对照清单 `cat` 环境文件 → 构建 → 部署 → 立即 `curl` 线上 `robots.txt`、sitemap 和一条 canonical URL。三十秒的偏执，防住两大经典事故（站点意外 noindex；站点意外暴露预览构建）。

## 缓存拓扑

- **静态资源**（JS chunk、字体、图片）：CDN 边缘给远期缓存头，文件名带内容哈希——永远缓存，靠不复用名字来失效。
- **HTML**：边缘短 TTL。营销页不常改，但真改了，修复应当分钟级可见，而不是等全球缓存到期。紧急更正走显式缓存清除——那是文档化、演练过的动作，不是口口相传的偏方。
- **动态面**（工具页、账号页）：边缘永不缓存；会话安全的响应头由应用设置。

字体构建期自托管，字体加载从不依赖第三方可用性，也不给首屏增加一次跨域 DNS 往返。

## 重构前先录黄金母版

部署管线里最值钱的习惯是录制纪律：**碰任何渲染页面的代码之前**，先把核心页面的渲染 HTML 录成黄金母版（按语言范围各录一套）；**之后**，diff 必须为空。「我看是一样的」不是回归测试。基线必须录自**旧**代码——重构完再录，等于把 bug 录成了标准。

## 发版清单（浓缩版）

1. 环境文件对照白名单审计（两道门都查：Dockerfile `ARG`、compose args）。
2. 黄金母版 diff 全绿（所有生效 scope）。
3. 交互路由过包体预算检查。
4. 部署 → 线上冒烟：`robots.txt`（索引状态正确）、`/sitemap.xml`（语言矩阵正确）、每个语言抽一条 canonical 返回 200 且没有尾斜杠 308。
5. 干净会话验证统计/心跳。
6. 路由有变则重提 sitemap；用户在等的修复发完即清缓存。

## 回滚阶梯，按烈度递增

1. **功能级开关** —— 关功能，保留发版。
2. **scope/环境开关 + 重建** —— 把部署拨回上一档行为（如下线一个语言）。
3. **代理层 301 映射** —— 动任何可能已被搜索引擎收录的路由之前，先架重定向。删除永远在重定向之后。
4. **回切上一版镜像** —— 重部署最近的已知良好构建；数据独立，镜像可换。

阶梯背后的铁律：**回滚永远不能把已收录 URL 变成 404。** 重定向承接收录权重；404 把权重白白送人。

## 可观测与备份

- 产品指标用自托管无 Cookie 统计；服务器日志送出本机备查；`/` 与工具路由挂存活检查。
- 备份：数据库文件与用户媒体，每日，落到**不是**生产机的存储上——并且做过恢复演练，没演练过的备份叫许愿，不叫备份。

## 写给从零开始的团队

1. 元数据生成器和 sitemap/hreflang 断言，放在**上线周之前**建好——事后补 SEO 管道是苦役。
2. noindex kill switch 从第一天就存在，并默认安全。
3. 引擎/供应商永远隔着一层薄内部接口；每个 AI 供应商都承诺可用性，没有一家承诺价格稳定。
4. 小规模下，两个隔离的区域部署胜过一套聪明的多租户系统。
5. 把建站过程写下来。未来的你和你的队友，都会因此出活更快。
