# 02 · 技术栈 —— 网站由什么构成

[English](../en/02-tech-stack.md) · `简体中文` · [日本語](../ja/02-tech-stack.md) · [한국어](../ko/02-tech-stack.md) · [Deutsch](../de/02-tech-stack.md) · [Italiano](../it/02-tech-stack.md) · [Español](../es/02-tech-stack.md)

## 框架

Next.js 16 + App Router、React 19、TypeScript、Tailwind CSS。设计工具内的状态收敛为一个 Zustand store；动画少量使用 Framer Motion；基础组件来自 Radix。格式化用 Biome，加 ESLint，两者都过才算过。

整套技术栈里，两个配置最要紧：

- **服务端组件优先。** 营销页、定价页、法务页全部服务端渲染，客户端 JS 接近于零。客户端包体只集中在真正需要交互的地方：设计工具。
- **`output: 'standalone'`。** 每个生产产物都是自带运行时的独立包——这正是 Docker 镜像得以瘦身、两个区域部署得以完全一致的前提（见 [05 · 部署](05-deployment.md)）。

## 生图管线

核心循环，简化后：

1. **上传。** 一张照片，上限 10 MB，仅 JPEG/PNG/WebP——客户端校验为了体验，服务端再校验为了真相。
2. **建任务。** 客户端提交房型、最多 4 个风格 ID 和/或自由描述（上限 500 字）与照片，拿到任务 ID 后轮询。
3. **Prompt 只在服务端拼装。** 这一点值得强调：客户端只传**风格 ID**。把风格预设变成图像模型提示词的文字碎片只存在于服务端，从不进客户端包。那是产品的配方本。
4. **生成。** 任务引擎把任务路由到 Flux 系图像模型，经托管服务商 API 调用，中间隔一层薄内部网关。网关的存在理由是让引擎可以按功能/档位替换而不动产品代码——供应商锁定是定价风险，所以从第一天就抽象掉。
5. **交付。** 前后对比图渲染进结果页；一次渲染扣一分，渲染失败在任务引擎层自动退款——不需要人工客服介入。

图片入库前用 sharp 后处理（缩放、编码、清洗）。上传与结果默认隐私：`robots.txt` 里禁抓，代理层再补一道 `X-Robots-Tag: noindex`，双保险保证用户照片不进图片搜索。

## 账号、积分、支付

- **登录。** Google（One Tap）与 Microsoft OAuth，外加邮箱链接。会话是签名 JWT（JOSE）。我们自己不存密码，也就没有密码可泄。
- **积分。** 积分是渲染的计量单位。余额、套餐、退款都在数据库旁一小层记账逻辑里；失败退款由任务引擎自动完成。
- **支付。** 国际收单走 **Creem（merchant of record）**——支付侧的税务与合规由它扛，对全球销售的小团队是笔划算交易。中国站跑独立的本地化支付。Webhook 处理幂等且验签；计费路径上的任何东西都不信任客户端。

## 数据层

SQLite，经一层带类型的薄数据访问层读写。两个隔离部署、写入量温和的场景下，嵌入式数据库直接消掉一整个运维面（没有数据库服务器要打补丁；备份 = 拷文件）。哪天写入量说话了，需要改的也只有那一层。事务邮件走普通 SMTP。

## 分析与隐私

统计**自托管且无 Cookie**。没有第三方广告追踪，欧盟访客不需要同意横幅，也没有数据倒卖——这个决策是和 GDPR 姿态一起做的，不是事后补的。我们用漏斗分析的精细度，换来一句能对任何人说清的隐私承诺。对这个产品，这笔交易是对的。

## 值得抄走的自动化检查

- **黄金母版 HTML diff。** 任何触及页面渲染的重构之前，先录核心页面的渲染 HTML；重构之后 diff 必须为空。六语言的字典抽取就是靠这个做到零视觉回归的。
- **包体预算。** 设计工具的客户端 chunk 有明确的体积上限；超预算的字典与功能要么切分要么砍掉。
- **SEO 断言脚本化。** sitemap 条目、hreflang 互指闭环、canonical/OG URL（包括「canonical 必须真实返回 200」）由脚本检查，不靠肉眼。见 [04 · SEO 打法](04-seo.md)。
