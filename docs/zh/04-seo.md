# 04 · SEO 打法 —— 技术 SEO、结构化数据，与一个诚实的 AI 爬虫政策

[English](../en/04-seo.md) · `简体中文` · [日本語](../ja/04-seo.md) · [한국어](../ko/04-seo.md) · [Deutsch](../de/04-seo.md) · [Italiano](../it/04-seo.md) · [Español](../es/04-seo.md)

## 一个元数据生成器，零手写 meta

每个页面的标题、描述、canonical、Open Graph/Twitter 卡、robots meta、hreflang 集合，全部出自一个带类型的生成器。没有任何页面手写 meta——这正是 meta 漂移（重复 canonical、丢 hreflang、标题腐烂）无法悄悄发生的原因。元数据值得做，就值得生成。

## 面向 SEO 的 URL 与语言政策

- **子目录式语言路径**（`/ja`、`/de`……）：信号集中在一个域名上；子域分摊权重，参数分摊抓取。
- **永远不做 `Accept-Language` 自动跳转。** 它喂给 Googlebot 错误的语言变体，还会让 CDN 缓存按 UA 分叉。hreflang + 可见的语言切换器才是正确组合；自动跳转是诱人的错误答案。
- **公共页不用 Cookie 记忆语言**：首次访问必须对爬虫可复现。
- **`x-default` 指向英文**（默认语言体验）。

## hreflang：要么互指，要么不做

我们运行的规则：**hreflang 只连接真实的 1:1 等价页，且集合内每一员必须互指。** 核心页（首页、工具页、定价页）构成一个完整的、生成的、脚本校验过的互指簇。

本地化编辑内容**不进**互指簇：我们的分语言指南是给每个市场原生撰写的——选题不同、角度不同——不是等价页，把它们标成等价就是拐着弯对搜索引擎说谎。非等价的本地化页面拿干净的 self-canonical，不带 `alternates`。如果只能在「不完整的 hreflang」与「说谎的 hreflang」之间二选一，那就两个都不要。

sitemap 条目执行同一政策：只在等价 URL 上输出 `xhtml:link` alternates，按「路由 × 语言」矩阵生成，法务页只有英文条目。

## Canonical 卫生（一个真实上线过的 bug）

有一段时间，语言首页产出的 canonical 形如 `/ja/`——带尾斜杠——而站点的规范 URL 形式是无斜杠的。每一条 canonical 和 `og:url` 都指向一个 308 重定向。GSC 把它报成「网页会重定向」，重复信号随之稀释，而浏览器里一切看起来正常。两个修复，如今都是永久纪律：

1. 在拼装 canonical 的出口处归一化尾斜杠（根路径 `/` 除外）；
2. 断言脚本解析每条 canonical/OG URL 并要求 HTTP 200——会 3 跳的 canonical 按构建失败处理。

## 结构化数据，做减法

- **做**：`Organization`（含 legalName）、`WebSite`、`SoftwareApplication`——`availableLanguage` 从生效语言列表生成，不写死。语言变了，schema 跟着变。
- **刻意不做**：`FAQPage` 富结果。Google 已把 FAQ 富结果限制给知名权威站点，新域名做这个标记没有收益。schema 按预期收益决策，不按清单从众。

## 图片搜索

室内设计是视觉检索的重度类目。每张展示渲染图在每个语言下都有本地化 `alt`、描述性文件名和快速分发。这是搜索之后最便宜的可复利流量渠道。

## AI 爬虫：喂答案，不给抓取预算

`robots.txt` 跑三层政策：

| 代理类别 | 允许 |
|---|---|
| 搜索引擎 | 公共页面；上传/结果与账号区禁抓 |
| AI 助手（GPTBot、Claude、PerplexityBot……） | 仅 `/llms.txt` 与 `/llms-full.txt` |
| 其他 | 标准公共白名单，crawl-delay 1 |

AI 这一行是立场不是疏忽：面向 LLM 的机器人不需要爬营销站，它们需要**准确且最新的事实**。所以我们发布 `llms.txt`（精选索引：Roomake 是什么、工具怎么用、6 房型 × 34 风格、定价模型、语言版本、官方链接）与 `llms-full.txt`（展开版），并把 AI 爬虫明确指到这两个文件。当助手回答「Roomake 是什么」时，我们宁愿它引用我们自己写的摘要，而不是从六个缓存页面里拼一个。这两个文件与结构化数据同源生成，同样不会与现实漂移。

## 关键词：原生词，不是翻译词

直接翻译英文关键词，在本地搜索量为零。每个市场拿到为当地人真实搜索习惯写的**原生种子词表**，例如：

- **日语**：AI インテリア、インテリア AI、リフォーム プレビュー、室内シミュレーション
- **德语**：KI Inneneinrichtung、Wohnraum KI gestalten、Renovierung visualisieren
- **韩语**：AI 인테리어、집 꾸미기 AI、리모델링 시뮬레이션

种子词有机落进标题/描述、分市场指南选题和语言元数据——绝不堆砌，堆砌会被搜索引擎打折、被读者惩罚。

## 度量与验证

- Google Search Console + Bing 站长工具，按站点分别配置，发版即提交 sitemap。
- **从渲染结果验证。** `curl` 看源码可能与浏览器/爬虫实际所见不一致（注入标签、水合变更、缓存层）。断言跑在渲染后的 DOM/HTML 上，不只看源码。
- 排名之外，我们盯的前导指标：各语言收录页数、GSC 的 hreflang 错误、图片搜索展示、AI 机器人对 llms 文件的抓取。

## 隐私在必须处压过 SEO

用户上传与生成结果永远不进搜索——`robots.txt` 禁抓，代理层 `X-Robots-Tag: noindex` 双保险。用户的卧室照片不是内容营销素材。有些页面就是不属于索引。

## 软启动：一个开关隐藏全站

内测期，一个构建期 `NOINDEX` 开关让 `robots.txt` 对全部内容 `Disallow: /`。这个开关**默认安全**（发版漏了环境配置行，结果是站点隐藏而不是意外公开）；切到公开索引后，发版第一步就是读线上 `robots.txt` 验证——与一切 kill switch 相同的纪律：默认关闭，切换后验证。
